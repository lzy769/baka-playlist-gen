# 工作原理

`baka-playlist-gen` 把「人类可读的歌曲列表」转换成「BakaMusic 可直接播放的歌单插件」，
核心难点在于 **歌名/歌手 → 平台歌曲 ID 的准确映射**。

## 为什么需要「严格二次校验」？

不同平台对同一首歌的收录版本差异巨大：

- 同一首歌可能有 **原版 / remix / live / 纯伴奏** 等不同条目；
- 搜索接口返回的「第一名」不一定是要的那版；
- 如果只按搜索接口的返回直接取 `mid`，很容易出现「**歌名显示 A、播出来却是 B**」的错配。

因此本工具采用「**搜索候选 → 逐条用真实信息反查 → 两端比对**」的严格策略，杜绝错配。

## 匹配流程（`src/matcher.js`）

```
输入: { title: "夜的第七章", artist: "周杰伦" }

① 搜索候选
   QQ 带签名搜索接口 (musics.fcg + zzcSign)
   按 "夜的第七章 周杰伦" 搜 8 条候选
   → [{ mid: "...", name: "...", singer: "..." }]

② 反查真实信息
   对每个候选 mid，调 CgiGetTrackInfo
   → 拿到该 mid 真正对应的 { name, singer }

③ 严格比对
   真实 name 与目标 title 匹配（忽略 remix/live/括号等后缀）
   真实 singer 与目标 artist 匹配（任意一个歌手对上即可）
   两端都通过才采纳该 mid

④ 决策
   有匹配 → 记录 mid，标记 verified
   无匹配 → 标记 unverified，绝不硬配
```

### 字符串归一化

比对前做归一化，避免格式差异误判：

- 小写化、`&`→`/`、`feat.`→`/`
- 去掉括号 / 方括号内容
- 去掉 `remix|live|version|mix|explicit` 等版本后缀

## 语言分组（`src/language-detect.js`）

判断依据（优先顺序）：

1. **韩文**：标题含韩文音节 `가-힣`
2. **日文**：标题含平/片假名；或标题为汉字但歌手名含假名 / 命中常见日文歌手名单
3. **中文**：标题含汉字（且非上述日文情形）
4. **英文**：标题主体为拉丁字母
5. **其他**：俄文、阿拉伯、纯数字/符号等

> 中日同形汉字（如「怪物」「春泥棒」）自动判别的边界是难点，
> 工具通过「歌手名是否带假名 / 是否命中日文艺人名单」辅助修正，
> 覆盖绝大多数常见歌曲；极少数边界情况可能归错组，可接受。

> 判别依据的是**歌名词面语言**，不依歌手国籍。例如韩国团体 BTS
> 的英文歌名《Dynamite》会归入「英文」而非「韩文」；只有歌名带韩文
> 音节（如《사랑을 했다》）才归「韩文」。如需调整，可直接编辑
> `src/language-detect.mjs` 中的规则。

分组可用 `--langs` 自定义启用，跳过不需要的组。

## 插件模板（`src/plugin-gen.js`）

每个语言生成一个 BakaMusic 单文件插件（CommonJS），实现：

| 方法 | 作用 |
|---|---|
| `importMusicSheet` | 输入触发码 `local://import` 导入完整歌单 |
| `getRecommendSheetTags` / `getRecommendSheetsByTag` | 在「推荐歌单」中展示 |
| `getMusicSheetInfo` | 歌单分页 |
| `getMediaSource` | 用 mid 解析真实播放 URL |
| `getMusicInfo` | 补全歌曲信息 |

插件把歌曲 mid 内嵌为 JSON 数组，播放时用 `mid` 调解析接口换真实地址。

## 播放接口与合规

默认播放解析走第三方 `tang.api.s01s.cn`（QQ 音源），这是社区维护的聚合接口：

- **稳定性**：可能失效、被限流、需要 Cookie / 签名；
- **合规性**：绕过音源 / 会员限制可能违反服务条款，且涉及版权。

**正式分发 / 生产使用前，请自行评估是否需要替换为有授权的解析逻辑。**
替换方式：修改 `src/plugin-gen.js` 中的 `requestMusicUrl` 实现即可。

## 使用建议

- 歌曲量大（上千首）时，优先用 `.csv`（零依赖、快）；
- 匹配请保持默认并发（3）与间隔，避免触发 QQ 限流；
- 大批量一次性跑完可能触发限流，可分多次、或用 `--interval` 加大间隔。
